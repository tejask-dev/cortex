# Prior art

Cortex follows an established pattern: human-readable knowledge, a disposable retrieval index, and shared access for multiple agents. It does not invent persistent AI memory. The decisions below are architectural lessons from current upstream documentation, not copied implementations.

Reviewed **2026-10-19** using upstream GitHub READMEs, LICENSE files, default-branch commit metadata, and open issue reports. Dates refer to the latest default-branch commit observed, not an assertion that a release was tested. Open issues are attributed reports and feature requests; we did not reproduce their bugs. All nine repositories were unarchived at inspection. Counts and marketing rankings are deliberately omitted.

## Decisions informed by this review

These are Cortex design choices, not claims that upstream projects implement them identically:

- Keep private Markdown outside the public software repository. Treat SQLite as rebuildable, with atomic index transactions and invariant checks.
- Share one implementation across CLI and MCP so parsing, filters, chronology and diagnostics agree.
- Preserve source, status, confidence and dates. Generated inferences begin as candidates; retrieval must not silently upgrade them into facts.
- Use bounded search and explicit relationships first. Measure failure cases before adding embeddings, extractors or graph databases.
- Keep the initial server local and narrow. Installing an adapter, registering configuration, completing a protocol handshake and proving a model tool call are distinct evidence levels.

No upstream implementation files were copied for this review. Any future source reuse needs its own license and notice review; Cortex's MIT license does not replace upstream licenses.
